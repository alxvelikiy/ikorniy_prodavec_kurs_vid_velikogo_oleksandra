# Схема упражнений Duo-слоя — `v2/duo/content/urok_NN.json`

Один файл на урок. Проверка: `node v2/duo/tools/validate-duo.mjs [N ...]` (0 ошибок — обязательно).
Источник смысла — ТОЛЬКО текст урока `v2/text/lessons/urok_NN.md` (и уже размеченные данные тренажёра
`window.TRAINER` в `v2/site/assets/trainer-data.js`: rules, quiz, pairs, quotes, scenes, says, terms —
всё это дословные фрагменты уроков). Методика наставника — истина: стартовое предложение новому клиенту
— с великого сету; виявлення потреби перед пропозицією — необов'язковий крок; норма — 75 дзвінків.

```jsonc
{
  "lesson": 4,
  "nodes": [                      // 1–3 узла на урок
    {
      "id": "u04-1",              // uNN-k, k = 1..3 по порядку
      "title": "Раннє «не треба»",// ≤ 32 символа, показывается в поповере пути (можно своими словами)
      "steps": [ /* 8–15 шагов; первый — theory */ ]
    }
  ]
}
```

## Общие поля шага

| Поле | Обяз. | Что |
|---|---|---|
| `id` | да | `uNN-k-sM`, уникален в уроке |
| `type` | да | `theory` · `choice` · `build` · `match` · `order` · `fill` · `spot` · `truefalse` |
| `source` | да | `existing` — весь контент дословно из урока; `generated` — часть текста сформулирована тобой |
| `generated` | если generated | список путей полей, которые НЕ дословны: `["options.2.text", "statement"]` |
| `refs` | если generated | 1–3 дословных фрагмента урока, на которых основан шаг |
| `note` | если generated | одна фраза для проверяющего: что именно придумано и на что смотреть |
| `lessons` | нет | номера уроков-источников, если текст дословно из другого урока (по умолчанию `[lesson]`) |
| `rule` | нет | код правила урока (`"4.1"`), к которому относится шаг |
| `why` | для упражнений | одна строка «чому» (≤ 160 симв.), показывается после ошибки. Дословно из урока (или в `generated`) |
| `prompt` | нет | инструкция интерфейса («Клієнт каже…», «Склади фразу») — не проверяется на дословность |

Проверяются на дословность (если не перечислены в `generated`): `text`, `title` (у theory), `context`,
`question`, `options.N.text`, `options.N.why`, `answer`, `full`, `before`, `after`, `pairs.N.left/right`,
`items.N`, `lines.N.text`, `statement`, `why`, `example`. Дословность = фрагмент есть в тексте урока после
нормализации (регистр, кавычки «»/"", апострофы, тире, пробелы не важны; допускается «…» на обрезанном краю).
Запрещено везде: частки «N з M» (они скрыты на сайте), стоп-лист SPEC §7 (`2/4`, эмодзи, коды K01…),
цифры в `generated`-полях, которых нет в `refs`.

## Типы

- **theory** — `title`, `text` (≤ 420 симв., один экран), опц. `example` (фраза менеджера). Первый шаг узла.
- **choice** — «Клієнт каже…» → лучший ответ менеджера. `context` (реплика клиента, опц.), `question` (опц.),
  `options`: 2–4 × `{ text, correct, why? }`, ровно один `correct: true`. Неверные варианты — правдоподобные
  ошибки новичков из урока (Типові помилки, слабкі цитати, неверные варианты тестов), а не абсурд.
- **build** — собрать фразу скрипта из плиток. `context` (опц.), `full` (вся фраза дословно), `answer`:
  плитки по порядку (3–10 плиток по 1–4 слова; склеенные через пробел = `full`), `distractors`: 0–4 плитки.
- **match** — `pairs`: 3–5 × `{ left, right }` (заперечення ↔ прийом, термін ↔ визначення, помилка ↔ як правильно).
  Левые и правые — уникальны. Короткие (≤ 90 симв.), иначе не влезут в плитки.
- **order** — `items`: 3–7 шагов в ПРАВИЛЬНОМ порядке (плеер перемешает), опц. `full` — исходное предложение.
- **fill** — `before` + [пропуск] + `after`, `answer`, `options`: 3–4 (включая `answer`). `before + answer + after`
  = дословная фраза урока. Неправильные опции обычно generated → пометить `options.N`.
- **spot** — «Знайди помилку менеджера»: `lines`: 3–6 × `{ who: "client"|"manager", text, wrong? }`, ровно одна
  `wrong: true` (реплика менеджера). `why`.
- **truefalse** — «Правда чи міф?»: `statement`, `answer` (true/false), `why`. Ложное утверждение — всегда generated.

Шаги-повторы ошибок, сердца, XP, комбо — логика плеера, в данных их нет.
