# Бриф content-adapter: уроки → упражнения Duo-слоя

Роль: `.claude/agents/content-adapter.md`. Схема (закон): `v2/duo/SCHEMA.md`. Валидатор: `node v2/duo/tools/validate-duo.mjs N` (из папки `_duo`) — 0 ошибок обязательно.

## Контекст
Новичок-менеджер Ikorka Shop звонит постоянным клиентам магазина икры; курс на 5 дней, 12 уроков, интерфейс на украинском.
Каждый урок превращаем в 1–3 «узла» пути в стиле Duolingo: короткая теория-карточка и 8–15 упражнений. Цель обучения —
рост Апрува и СРЧ: упражнения тренируют правильные фразы и решения из методики, а не «кликанье».

## Что читать
- `v2/SPEC_v2.md` §2 (терминология: сет, заперечення, допродаж, наставник, Odoo, «повернення клієнта») и §7 (стоп-лист).
- Полный текст своих уроков `v2/text/lessons/urok_NN.md`.
- Размеченные данные тренажёра (дословные, проверенные): из `_duo` выполнить
  `node v2/duo/tools/trainer-lesson.mjs N` — печатает rules, quiz, pairs (bad → good + why), quotes (сильні/слабкі + why + instead),
  scenes (реплика клиента, варианты good/why), says («Скажи так»), open, practice и термины урока.
- Не использовать неперевірені твердження скрипта компанії: `v2/mvp/content/unverified_exclusions.json`, `v2/mvp/PHRASES_FOR_REVIEW.md`.

## Методика наставника — истина (нигде не противоречить)
Стартовое предложение новому клиенту — с великого сету; одне-два уточнювальні питання / виявлення потреби перед пропозицією —
необов'язковий крок; норма — 75 дзвінків; клиенту не задают вопрос «чому» (урок 4); всё прочее — как написано в уроке.
Не выдумывай цифры, проценты, цены, факты — цифры только из текста урока. Доли «N з M» не использовать (на сайте скрыты).

## Как строить (на каждый урок)
- 2 узла по 10–13 шагов (1 — если урок короткий; 3 — если очень богатый). Узел 1 — ядро, узел 2 — углубление/отработка.
  `title` узла — короткий (≤ 32 симв.), живой.
- Шаг 1 каждого узла — `theory`: ключевая мысль дословно (правило или абзац, ≤ 420 симв.), `title` — дословный фрагмент;
  опционально `example` — дословная сильная фраза менеджера.
- Дальше — смесь ≥ 4 типов, без двух одинаковых подряд, сложность растёт к концу узла:
  - **choice** — из scenes (реплика клиента → варианты с good/why) и quiz. Неверные варианты — РЕАЛЬНЫЕ ошибки новичков из урока
    (Типові помилки, слабкі цитати, неверные варианты теста), а не абсурд. `why` — дословное пояснение из урока.
  - **build** — из says («Скажи так») и сильных цитат: фраза дословно в `full`; `answer` — осмысленные куски по 1–4 слова
    (3–10 плиток; склеиваются через пробел в `full`, знаки препинания прилипают к слову); `distractors` — 2–3 правдоподобные
    плитки (часто слова из типичных ошибок: «чому», «знижку»…) → шаг `generated`, в `generated` указать `distractors`.
  - **match** — термін ↔ визначення, помилка ↔ як правильно (короткие), заперечення ↔ прийом; 3–5 пар, стороны ≤ 90 симв.
    (длинное — дословный кусок с «…»).
  - **order** — только если порядок ЯВНО задан в уроке (стрелки «→», нумерованные шаги, «спершу… потім…»): 3–7 пунктов дословно.
  - **fill** — ключевое слово/словосочетание в дословной фразе; `options` 3–4, неверные — правдоподобные (`generated`: `options.N`).
  - **spot** — «Знайди помилку менеджера»: 3–5 реплик; реплика клиента и хорошие реплики менеджера — дословно, ОДНА ошибочная
    реплика менеджера — дословно из Типових помилок/слабких цитат; `why` — дословно.
  - **truefalse** — «Правда чи міф?»: верное = дословное правило; ложное = искажение по описанному в уроке заблуждению новичка
    (`generated`, `refs` — искажённое правило).
- Цель — ≥ 70 % шагов `existing`. Каждый generated-шаг: `generated` (пути полей), `refs` (1–3 дословных фрагмента-основы),
  `note` (что придумано, на что смотреть проверяющему).
- `prompt` — живая короткая инструкция на украинском («Клієнт каже…», «Обери найкращу відповідь», «Склади фразу», «Поєднай пари»,
  «Розстав по порядку», «Встав пропущене», «Знайди помилку менеджера», «Правда чи міф?») — можно разнообразить, без канцелярита.

## Правила работы
Папка `_duo` — git worktree ветки design-duo. Работай ТОЛЬКО с файлами `v2/duo/content/urok_NN.json` своих уроков. Не делай git
commit/checkout/stash, не запускай build и полный прогон тестов. В Bash-командах не используй обратные кавычки (backticks) — в этой
оболочке они ломают команду. Если инструмент временно отказывает с ошибкой классификатора — повтори один раз, затем продолжи
другой частью задачи. Делай по одному уроку и сразу валидируй. Перечитай смысл: нет противоречий уроку и методике, правильный ответ
однозначен, неверные варианты правдоподобны.

Отчёт в конце (≤ 20 строк): по каждому уроку — узлы, шаги, типы, доля generated; спорные места для проверки человеком.
