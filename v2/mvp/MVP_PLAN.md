# MVP_PLAN — интерактивный тренажёр курса новичка Ikorka Shop

Ветка `mvp` (от `master`). Ветку `pipeline`, `v2/corpus/*`, `v2/audit/*` не трогаем (аудит только читаем). Без push/PR.

## Архитектура

- **Сборка:** существующий `v2/build/build.mjs` (без npm-зависимостей) расширяется, а не заменяется. Уроки остаются в `v2/text/lessons/*.md` — единственный источник текста.
- **Данные тренажёра:** `v2/build/lib/trainer.mjs` на сборке (1) автоматически вынимает из уроков тест «Перевір себе», пары «Типові помилки», цитаты «Сильно/Слабко», фразы «Скажи так», пункты «Практика»; (2) подмешивает курируемую разметку `v2/mvp/content/urok_NN.json` (коды правил, «спроба до пояснення», «чому/що сказати» к вопросам, сцены симулятора, термины); (3) валидирует **каждый** фрагмент дословно по тексту урока; (4) пишет `assets/trainer-data.js` (`window.TRAINER`). Невалидный элемент не попадает на сайт, а пишется в отчёт сборки.
- **Рантайм:** `assets/trainer.js` + `assets/trainer.css` (ванильный JS, как весь сайт; прогресс в `localStorage` с try/catch, экспорт/импорт JSON). ИИ-клиент: `assets/coach.js` → только `/api/coach/roleplay` и `/api/coach/feedback`.
- **Сервер ИИ-тренера:** `v2/coach/server.mjs` (Node без зависимостей) раздаёт `v2/site` и проксирует Anthropic Messages API. Ключ только из `ANTHROPIC_API_KEY`, модель — `COACH_MODEL` (по умолчанию `claude-sonnet-5`), `COACH_MOCK=1` — мок для тестов. Без сервера (или без ключа) сайт работает полностью, тренер — «офлайн» (разбор по правилам уроков).
- **Цифры:** флаг `SHOW_STATS` (по умолчанию выключен). Доли «N з M» с базой 26 / базой наставника / неподтверждённой базой не показываются: `:::stat` с такой долей и внутренним источником не рендерится, строки текста с долями правятся по таблице `v2/mvp/content/stats_redactions.json` (только удаление числа, каждая правка перечислена). `SHOW_STATS=1 node v2/build/build.mjs` возвращает исходный текст. Внешние исследования остаются с источником; `:::stat` с источником «записи навчання з наставником» / «методичка наставника» — с меткой «Слова наставника».

## Контентная карта (откуда каждый элемент; `source_ref` = урок + дословный фрагмент)

| Элемент интерфейса | Источник | Как проверяется |
|---|---|---|
| Коды правил урока (3–5, «Правило N.k») — в начале урока, в SOS, в итоговой проверке, в цели на звонки | `urok_NN.json → rules[].text` — дословный фрагмент урока | валидатор + автотест `source_ref` |
| «Спроба до пояснення» (1–2 на урок) | вопрос и варианты — тест «Перевір себе» урока (A/B/C), правильный ответ — оттуда же; пояснение `attempts[].explain` — дословно из раздела, перед которым стоит вопрос | то же |
| Разбор в 3 строки к вопросу теста | «Що сказано» = выбранный вариант (дословно); «Чому» = `quiz[n].why`; «Що сказати натомість» = `quiz[n].say` | то же |
| Карточки «Типові помилки → Як правильно» (сначала выбор) | `:::pairs` урока; варианты — «як правильно» этой и соседних пар того же урока; «Чому» = `pairs[i].why` | то же; пары с пустым «як правильно» не превращаются в выбор |
| «Сильно чи слабко?» в тесте урока | `:::quote` урока (текст, оценка, «чому»); «Що сказати натомість» для слабкой = `quotes[i].instead` | то же |
| Тест в конце урока | MCQ «Перевір себе» + цитаты + до 3 пар; неверные повторяются; порог 80 % с первой попытки | автотест |
| Открытые вопросы (пригадування) | «Перевір себе» → «Звір себе:» (эталон дословно), самооценка «знав / частково / ні» | — |
| Повторення (1, 3, 7, 14 дней, ≤5 в день, слабые чаще) | те же карточки + личная колода | автотест |
| Симулятор (8–12 сцен) | `urok_NN.json → scenes[]`: реплика/ситуация клиента, 2–3 варианта менеджера, последствие — всё дословно из урока | валидатор + автотест |
| SOS «Я на дзвінку» | фразы `:::say` всех уроков, разделы урока 4 по видам возражений, таблица возражений компании (DOC-ZAP, `x/zaperechennya.docx.txt`) с меткой «скрипт компанії», скелет звонка — урок 3 | данные вшиты в страницу (офлайн) |
| Персоны ИИ-клиента | возражения из DOC-ZAP (істинні / ситуативні / хибні), дословно; скрытая причина для хибних — из ответа DOC-ZAP | сервер: заземление ≤3 КБ |
| Разбор ИИ-тренера | правила и фрагменты урока сцены; каждая рекомендуемая фраза проверяется дословно по урокам, иначе «У курсі немає готової фрази — див. правило N» | мок-тест валидатора |
| Термины (тап по термину) | `urok_NN.json → terms[]`: определение дословно из урока | валидатор |
| Итоговая проверка | MCQ + цитаты всех 12 уроков вперемешку, порог 80 %, карточка слабых тем | автотест |
| «Як супроводжувати новачка» (режим руководителя) | коды правил + «Практика» каждого урока, дословно | `source_ref` |
| Маршрут по дням | структура дней из сборки (уроки 1–3 / 4–5 / 6–8 / 9–11 / 12) | — |

Не выдумывается: вопросы, варианты, реплики клиента, «Як правильно», пояснения. Где материала нет — элемент не показывается и попадает в MVP_REPORT как «потрібен контент».

## Правила интерфейса (из ТЗ)

- Всплывающие окна: никогда при загрузке; не больше одного на раздел; только в паузе (конец H2); немодальные (drawer/toast); фокус возвращается; «Пропустити» всегда видно. «Ви зупинились на…» — встроенная плашка в тексте урока, не всплывашка.
- Разбор любого ответа — три строки: «Що сказано → Чому це погано/добре для клієнта → Що сказати натомість (дослівно з уроку)». Голое «Правильно/Неправильно» запрещено.
- Геймификация минимальна: кольцо прогресса и дни навчання без штрафа за пропуск.
