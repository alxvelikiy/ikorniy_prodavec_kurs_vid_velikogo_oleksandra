# DECISIONS — DUO-редизайн (ночной прогон 2026-09-28, ветка `design-duo`)

Формат: Вопрос / Варианты / Выбрано / Почему / Как откатить. Пользователь спал — все решения принял Lead.
Пометка **[перепроверить]** — стоит посмотреть утром.

### D-001. Откуда брать ветку `public-deploy`
- **Вопрос:** в локальном репо нет `public-deploy` (только `master`, `pipeline`); рабочая копия на `pipeline` с чужими незакоммиченными файлами (`v2/corpus/cards/*`, бандл, zip).
- **Варианты:** (а) checkout в основной папке; (б) отдельный git worktree.
- **Выбрано:** `git fetch origin public-deploy`, worktree `_duo/` (внутри проекта, исключён локально через `.git/info/exclude`, в `pipeline` не виден) на новой ветке `design-duo` от `origin/public-deploy` (e50f9a7). Апстрим отвязан (`--unset-upstream`), чтобы `git push` не мог уйти в `public-deploy`.
- **Почему:** основная папка и ветка `pipeline` (другая сессия, волны корпуса) не трогаются вообще.
- **Откат:** `git worktree remove _duo` и `git branch -D design-duo`; строку `/_duo*/` из `.git/info/exclude` можно оставить.

### D-002. Окончания строк в worktree
- **Вопрос:** системный `core.autocrlf=true` (Git for Windows) выдаёт файлы с CRLF → SHA-пин `vendor/supabase-js.js` не сходится, `static-checks` падает.
- **Выбрано:** `extensions.worktreeConfig=true` + только для `_duo`: `core.autocrlf=false`, `core.eol=lf` (как на Linux/Netlify). Основная папка не затронута.
- **Откат:** `git config --worktree --unset core.autocrlf` (в `_duo`).

### D-003. Тесты на Windows: базовая линия 334
- **Вопрос:** 334/334 были получены в облачной Linux-песочнице (postgresql-16 через sudo). Здесь Windows: 307 ок / 5 падений, RLS пропущен.
- **Выбрано:** починить окружение, не ослабляя проверки: RLS — настоящий Postgres 18.4 из npm `embedded-postgres` (опциональная dev-зависимость тестов, бинарники копируются в ASCII-путь, т.к. initdb не переносит кириллицу «Аудио…» в пути); `static-checks` — два git-вызова вместо `a; b` (в cmd.exe проверка ключей тихо проверяла 0 файлов); `coach-function-test` — корректное завершение (падение libuv на Windows); `account-e2e` — не считать ошибкой `/assets/…` запрос, прерванный самой перезагрузкой страницы. Итог: **334/334** на Windows (коммит 053af62).
- **Откат:** `git revert 053af62`.

### D-004. Главная = путь, старая «Сьогодні» → `sogodni.html`
- **Вопрос:** спецификация требует путь на главной, но существующие e2e-тесты проверяют старую «Сьогодні» на `index.html`.
- **Варианты:** (а) путь на отдельной странице, index не трогать; (б) путь на index, старая страница переезжает; (в) всё за флагом.
- **Выбрано:** (б). `index.html` — путь (и онбординг для нового пользователя как содержимое страницы, не диалог). Старая «Сьогодні» без изменений переезжает в `sogodni.html` (там экспорт/импорт файла прогресса, итог перевірки готовності); в e2e меняется только адрес страницы — сами проверки те же.
- **Почему:** корень сайта должен открывать новое приложение; функциональность старой страницы и её тесты сохранены.
- **Откат:** в `v2/build/duo/build-duo.mjs` отключить генерацию `index` (флаг `DUO_HOME=0`) — вернётся старая главная.

### D-005. Данные упражнений — в `/data/`, а не в `/assets/`
- **Вопрос:** edge-функция гейтинга пропускает `/assets/*` без входа — всё, что там лежит, публично.
- **Выбрано:** упражнения и карта курса генерируются в `v2/site/data/*.js` (под гейтингом). Стили/скрипты/шрифты — в `/assets/duo/` (нужны и странице входа).
- **Заметка:** существующий `assets/trainer-data.js` (весь текст уроков) уже сейчас публичен — это было до нас; не трогаю, но **[перепроверить]**: возможно, стоит перенести и его.
- **Откат:** поменять путь в `build-duo.mjs`.

### D-006. Архитектура фронтенда без фреймворка
- **Выбрано:** классические `<script defer>` + неймспейс `window.Duo`, модули-IIFE по владельцам (см. `ARCHITECTURE.md`). Без бандлера и npm-зависимостей в рантайме — как весь проект.
- **Почему:** бюджет JS ≤ 80 KB gzip, ноль сборочной инфраструктуры, параллельная работа агентов по файлам.

### D-007. Шрифт — Nunito, self-host
- **Выбрано:** вариативный Nunito (OFL-1.1) из npm `@fontsource-variable/nunito@5.3.0`, 2 файла: `nunito-cyrillic.woff2` (20 KB) + `nunito-latin.woff2` (38 KB), `font-display: swap`, preload кириллицы. Google Fonts на Duo-страницах не грузим.
- **Откат:** заменить файлы в `v2/build/assets/duo/fonts/`.

### D-008. Тема оформления
- **Выбрано:** та же логика, что на старых страницах: `localStorage['ikorka-theme']==='dark'` → тёмная, иначе светлая; переключатель — в профиле. Системную тему автоматически не подхватываем, чтобы при переходе между старыми и новыми страницами тема не «мигала».
- **Откат:** в `duoShell()` добавить проверку `prefers-color-scheme`.
