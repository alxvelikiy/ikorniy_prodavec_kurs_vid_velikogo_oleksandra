# Teardown Duolingo — всё ВНУТРИ урока (экран вправи, фідбек, серця, завершення)

Разбор публичных материалов о Duolingo (mobile + web) внутри экрана упражнения: раскладка (крестик, толстый
скруглённый прогресс-бар с бликом, сердца), рост прогресс-бара после верного ответа и комбо-состояние, кнопка
CHECK и клавиатура на вебе, плитки word bank (перелёт FLIP), feedback-sheet «верно/неверно», очередь повторов
ошибок внутри урока (урок не закрывается, пока не решено), выход посреди урока и состояние «0 сердец», экран
завершения со статистикой, типы упражнений, Rive-анимации персонажей и звуковой дизайн уроков. Источники — тот
же круг, что и в companion-файле `docs/design/research/meta.md` (там — всё ВНЕ урока): официальный блог
Duolingo, публичные UX-кейсы и разборы механик, галереи микроанимаций, справочные вики. **Методологическая
оговорка:** в этой сессии инструменты живого поиска (WebSearch/WebFetch) стабильно возвращали ошибку
классификатора окружения (десять попыток подряд без вердикта, дальше рисковать нельзя было — турн мог
остановиться без результата), поэтому факты ниже реконструированы по уже известным Claude публичным
материалам на эту тему, без свежей проверки конкретных URL в моменте; это явно повышает долю `low` в таблице
против аналогичной работы с рабочим поиском. Там, где Duolingo не публикует точные цифры (длительность
анимации, Hz звука, точные пороги комбо) — значение реконструировано по общепринятым практикам игрового UI и
помечено `low`. В колонке «Наш аналог» — сопоставление с контрактами `docs/design/ARCHITECTURE.md`
(`Duo.motion`, `Duo.sfx/haptics`, `Duo.ui.sheet/modal`, `Duo.progress`, `Duo.copy`, `Duo.mascot`) и схемой
вправ `v2/duo/SCHEMA.md` (`choice/build/match/order/fill/spot/truefalse`); отдельно зафиксирован корпоративный
нюанс задания — сердца у нас не блокируют обучение надолго.

## Тайминги-сводка

| Событие | Длительность / easing | Наша рекомендация |
|---|---|---|
| Рост прогресс-бара (верно) | ~400–600 мс, spring/overshoot (low) | `springGrow`: cubic-bezier(0.34,1.56,0.64,1) или реальная spring (stiffness ≈300, damping ≈20) |
| Sheet вверх (feedback/exit) | ~250–350 мс ease-out на вход, ~150–200 мс на выход (low) | единые `Duo.motion.dur.base`/`.fast` для `sheetUp`/`sheetDown`, без отдельных чисел на каждый случай |
| Shake неверной карточки | ~300–400 мс, 3–4 угасающих колебания (med) | keyframes с уменьшающейся амплитудой, а не единичный cubic-bezier |
| Heart break | ~300–400 мс, лёгкий tremor перед сменой иконки (low) | синхронизировать конец с началом sheet «неверно» |
| FLIP плитки word bank | ~200–300 мс ease-out (med) | использовать уже спроектированный `Duo.motion.flip` без изменений |
| CountUp XP / точность | ~600–900 мс, ease-out с замедлением к финалу (med) | `countUp(el, from, to, {ms: 700})` + `xpTick` на каждый шаг |
| Stagger карточек статистики | шаг ~150–250 мс между карточками (low) | `Duo.motion.stagger(els, fn, 200)` |
| Confetti на завершении урока | ≤ 1.4–1.5 с (high — уже зафиксировано контрактом) | `confetti({ms: 1400})` без изменений |
| popIn (выбор варианта / бейдж комбо) | ~120–200 мс ease-out, overshoot до ~1.05 scale (low) | одна функция `popIn` на оба случая, не дублировать |
| Переход между шагами урока | ~150–200 мс fade/slide (low) | синхронизировать с началом `springGrow`, чтобы читалось одним движением |
| Idle-моргание маскота | цикл 3–6 с, только в viewport (med — совпадает с уже описанным в meta.md для пути) | тот же `Duo.mascot.mount({idle:true})`, не отдельная реализация для урока |
| Двойная вибрация «неверно» | 2 коротких импульса подряд (low) | `navigator.vibrate([40, 60, 40])` вместо одного числа |
